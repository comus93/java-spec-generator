> 대상 저장소: `comus93/java-spec-generator`

## 1. 목적과 설계 원칙

사내·고객사 레거시 Spring MVC 계열 프로젝트의 Java/JSP 소스를, 사용자 PC에서 **AI·외부 서비스·블랙박스 분석 실행기 없이** 정적 분석하여 **소스 파일 1개당 Excel 프로그램 사양서 1개**를 생성한다.

- Java와 JSP는 **별도 실행 모드**로 취급한다. 두 소스의 연결 관계를 추정하거나 매칭하지 않는다.
- 사양서는 **소스에서 실제 확인한 구문·속성·소스 위치**와 사용자가 입력한 공통값만 표현한다.
- AI가 작성한 업무 설명, 해석·평가, 가짜 호출 대상, 추측한 필드 값은 포함하지 않는다. 알 수 없는 값은 **공란**이다.
- 출력 스키마와 디자인은 기존 **그레이스케일 샘플 Excel 4종**을 기준선으로 삼는다.
- 소스 원본은 읽기 전용으로 접근한다. 로컬·오프라인 실행이며 외부 시스템에 원문이나 분석 결과를 전송하지 않는다.
- 사용자는 모듈 **폴더를 직접 지정**한다. Spring 패키지 경로를 추론해 시스템/서브시스템/모듈을 자동 분류하지 않는다.

### 목표로 하는 사용자 경험

Windows 데스크톱 GUI(Swing) 또는 CLI에서 Java/JSP 중 하나를 선택하고, 분석할 **모듈 폴더 여러 개**를 지정한 뒤 공통 설정과 폴더별 표시명을 편집한다. 실행기는 해당 폴더 아래의 해당 확장자 파일을 재귀적으로 탐색해 Excel을 만든다. 선택한 폴더의 **물리적 하위 계층**은 출력 폴더 아래에 그대로 보존된다.

## 2. 범위 및 명시적 비범위

### 포함

1. JavaParser 기반 `.java` 정적 구문 분석.
2. PMD JSP Parser 기반 `.jsp` 정적 구문 분석.
3. Java/JSP 각각에 대한 확정된 사양서 시트 구성과 원문 기반 데이터 변환.
4. Excel `.xls` 생성 및 `.xlsx` 선택 지원.
5. Swing GUI / CLI의 **공통 Java 실행 코어**.
6. 선택한 여러 모듈 폴더, 서브시스템/모듈 표시명 편집, 중복 경로 처리.
7. 보안·오프라인 배포, 처리 현황과 오류 기록, 재현 가능한 검증.

### 제외

- Java↔JSP 연결, Spring Controller↔JSP/URL 라우팅, 프로젝트 통합 호출 그래프의 의미 추정.
- 소스 실행·컴파일·웹 애플리케이션 기동, Spring 컨테이너 로딩, 데이터베이스 연결.
- AI/LLM, RAG, 벡터 검색, 인터넷 서비스, 코드 업로드.
- LeflectJava CLI/독립 바이너리, Node.js 분석 프로세스.
- JavaDoc에 없는 비즈니스 설명 자동 작성, 로직의 자연어 요약.
- Word/PDF 생성과 JSP 화면 렌더링, 네트워크에 의존하는 런타임 플러그인 다운로드.
- GUI 시안의 실제 구현 승인은 별도로 진행. **현재 UI 초안은 레이아웃 참고자료**다.

## 4. 입력 모델과 실행 단위

### 4.1 공통 설정

| 설정 | 의미 | 기본/동작 |
|---|---|---|
| 분석 유형 | `JAVA` 또는 `JSP` | 한 실행에서는 하나만 선택 |
| 시스템 | 사양서의 최상위 업무 분류 | 사용자 전역 입력 |
| 작성자 | 표제부 작성자 | 사용자 전역 입력, 미입력 시 공란 |
| 작성일 지정 (선택) | 모든 생성 사양서의 작성일 일괄 지정 | 미입력 시 **각 원본 파일의 파일시스템 최종 수정일** 사용. 지정 시 해당 날짜로 대체 |
| 프로그램명 | 표제부 프로그램명 | 선택적 전역 입력, 미입력 시 공란 |
| 프로그램 개요 | 표제부 프로그램 개요 | 선택적 전역 입력, 미입력 시 공란 |
| 출력 폴더 | Excel 생성 루트 | 사용자 입력 |
| Excel 형식 | `.xls` 또는 `.xlsx` | `.xls` 기본, `.xlsx` 선택 가능 |

'시스템 명'이라는 구 명칭은 사용하지 않는다. 표제부 계층은 **시스템 → 서브 시스템 → 모듈**이다.

### 4.2 모듈 폴더 목록

사용자가 여러 폴더를 **드래그 앤 드랍**하거나 **[+ 폴더 추가]** 버튼으로 추가한다. 각 행은 다음 세 항목을 가진다.

| 항목 | 초깃값 | 편집 |
|---|---|---|
| 서브 시스템 | 전역 **시스템** 입력값과 동일 | 가능 |
| 모듈 | 사용자가 선택한 **최상위 소스 폴더의 이름** | 가능 |
| 선택한 소스 폴더 | 사용자가 지정한 절대 경로 | 읽기 전용, 변경 시 다시 지정 |

- Drop Zone에 폴더를 다시 드롭하면 **기존 목록에 신규 폴더만 누적 추가**한다.
- 정규화된 **절대 폴더 경로**를 기준으로 중복을 제거한다. 모듈 이름이 같아도 경로가 다르면 서로 다른 항목이다.
- 기존 행에서 편집한 서브시스템·모듈명은 추가 드롭이나 시스템명 변경 때문에 덮어쓰지 않는다.
- 전역 시스템명이 수정되면 **개별 수정하지 않은 행**의 서브시스템 기본값만 함께 변경한다.
- 행마다 **제거(X)** 가능. 제거는 선택 목록에서만 지우며 소스 폴더 자체는 삭제하지 않는다.
- 모듈명 수정은 **Excel 표제부의 모듈 값만 변경**한다. 분석할 원본 경로·출력 디렉터리 이름에는 영향을 주지 않는다.

### 4.3 실제 프로젝트 구조 예

Java 선택 예:

```text
sys1_PJT1/src/main/java/ext/sys1/module1/  <- 사용자 선택
  config/*.java
  controller/*.java
  dao/*.java
  model/*.java
  service/*.java
  objects/*.java
```

JSP 선택 예:

```text
sys1_PJT1/src/main/webapp/ext/sys1/module1/ <- 사용자 선택
  jsp/*.jsp
```

같은 `module1` 이름이어도 Java/JSP 간 자동 탐색·병합·연결은 하지 않는다. Java 실행 시 `.java`만, JSP 실행 시 `.jsp`만 처리한다.

## 5. 출력 파일 및 경로 계약

### 5.1 1:1 출력

**선택한 소스 파일 하나 → Excel 하나.** 동일한 원본이 한 실행에 중복 생성되는 일은 없어야 한다.

```text
소스:
C:\SYS1_PJT1\src\main\java\ext\sys1\module1\
  controller\OrderController.java
  service\OrderService.java
  dao\OrderDao.java

출력 (D:\SpecOutput 선택 시):
D:\SpecOutput\
  module1\
    controller\OrderController.xls
    service\OrderService.xls
    dao\OrderDao.xls
```

- 출력 폴더 기준으로 **선택한 모듈 폴더명부터** 하위 경로를 복제한다. 프로젝트 전체 경로는 복제하지 않는다.
- 출력 파일명은 원본 **기본 이름 + Excel 확장자**다. 예: `OrderController.java` → `OrderController.xls`, `list-todos.jsp` → `list-todos.xls`.
- 실제 폴더 이름은 **사용자가 선택한 원본 폴더명**을 보존한다. GUI에서 수정한 모듈 표시명으로 경로를 바꾸지 않는다.
- 서로 다른 원본이 **한 실행에서 같은 출력 파일 경로**를 요구하면 임의로 한쪽을 선택하지 않고 사전에 충돌을 알린다. 이 경우 **기존 출력 파일의 재생성과는 구분**하며, 충돌한 서로 다른 원본 간 결과 혼합을 막는다.
- **기존 출력 폴더는 확인 없이 재사용**하고 없는 하위 폴더는 생성한다. **동일한 위치에 기존 Excel 파일이 있으면 사용자 확인 없이 무조건 덮어쓴다.** 폴더가 이미 존재한다는 이유로 차단하지 않는다.
- 폴더를 재귀 삭제하거나 해당 실행의 생성 대상이 아닌 다른 파일까지 삭제하는 정책은 포함하지 않는다. '폴더 포함 덮어쓰기'는 기존 폴더의 **재사용 및 그 안의 동일 경로 산출물 교체**를 뜻한다.
- 원본 소스를 수정하지 않고 출력 루트가 분석 대상 경로 안에 있으면 명시적으로 제외하거나 실행을 차단한다.
- `원본경로` 시트의 원본 위치는 **사용자가 선택한 로컬 소스 파일 경로**를 기록한다. 공개 예시 파일에 GitHub URL이 있더라도 사내 소스에 임의의 원격 URL을 만들어 기입하지 않는다.
- 동일 경로의 파일이 중복 선택되지 않도록 **폴더 경로 정규화 및 사전 검사**를 수행한다. 상위/하위 폴더의 동시 선택으로 인한 중복은 명시적으로 경고한다.

### 5.2 포맷 제약

- `.xls`는 Apache POI HSSF, `.xlsx`는 XSSF로 생성한다.
- `.xls`의 행·열·셀 문자열 등 포맷 고유 한계를 넘으면 **조용히 잘라내지 않고** 파일별 오류를 안내한다. `.xlsx` 전환을 선택할 수 있다.
- 원본 문자열은 **문자열 셀**로 기록하며 Excel 수식으로 실행되지 않게 한다.
- 사양서에 인위적인 긴 코드 전문을 덧붙이기보다 원래 시트 계약에 필요한 원문·위치·선언을 보존한다.

## 6. Excel 공통 외형 및 표제부

### 6.1 외형

- 모든 시트 **1행**은 제목, **2행의 분석기 설명 문구는 제거**한다. 2행에 `PMD JSP AST · ...`, `JavaParser AST · ...` 같은 문구를 쓰지 않는다.
- 모든 시트는 **무채색/그레이스케일**로 표현한다. 제목 진회색, 헤더 중간 회색, 본문 흰색·연회색, 가독성 있는 테두리·줄바꿈 사용.
- Excel 내 설명성 배너, "판정 근거", AI 추론 문장, 데이터가 없는 상태를 억지로 설명하는 문구를 추가하지 않는다.
- 정렬·머지·행 높이·열 너비·표 구조는 기존 그레이스케일 기준 샘플을 우선한다.
- 최종 `.xls`의 검증은 **값/공란/시트 구조/회색조 스타일**을 기준으로 하며, 서로 다른 Excel 파일 형식 사이의 바이너리 동일성을 요구하지 않는다.

### 6.2 모든 파일에 있는 `01_표제부`

첫 번째 시트 제목은 `프로그램 사양서`. 항목 **10개**를 아래 순서로 표시한다.

| 번호 | 항목 | 값 결정 |
|---|---|---|
| 01 | 시스템 | 공통 설정 |
| 02 | 서브 시스템 | 선택 모듈 행별 설정 |
| 03 | 모듈 | 선택 폴더명 초기값 또는 사용자가 수정한 표시명 |
| 04 | 프로그램 ID | 원본 파일명에서 확장자를 제외한 기본 이름 |
| 05 | 작성자 | 공통 설정. 미입력 공란 |
| 06 | 작성일 | **각 원본 소스 파일의 파일시스템 최종 수정일**. 사용자가 작성일을 지정했다면 해당 지정일 우선 |
| 07 | 프로그램명 | 공통 설정. 미입력 공란 |
| 08 | 개발 유형 | `Java` 또는 `JSP` |
| 09 | 프로그램 유형 | Java는 소스의 선언 유형(`Class` 등), JSP는 `JSP` |
| 10 | 프로그램 개요 | 공통 설정. 미입력 공란 |

작성일 기본값은 생성일·Git 커밋 날짜가 아니라 **각 원본 파일의 최종 수정일**이다. GUI에서 사용자가 작성일을 편집·지정하면 그 날짜를 적용한다. CLI에서는 설정 파일의 선택적 `authoringDateOverride`로 같은 기능을 제공한다. 미지정 시 파일 수정일을 사용하며, 수정일을 읽을 수 없다면 공란으로 남기고 파일별 경고를 기록한다.

## 7. Java 분석/출력 계약

### 7.1 분석

JavaParser를 라이브러리 API로 직접 호출한다. 소스 텍스트와 AST로 확인할 수 있는 다음 정보만 추출한다.

- 최상위·내부 타입 선언, 필드, 로컬 변수, 생성 시 초기값, 수식어, 소스 위치.
- 메서드 이름, 매개변수 **이름과 타입**, 반환 타입, 접근 제한자, 메서드 범위.
- `if`/조건분기, 반복문, `return`, 예외·객체 생성·대입·호출 등 소스 구문.
- 메서드 호출 표현식과 선언한 `import`, 타입 사용.
- JavaDoc이 실제로 존재하는 경우에만 해당 원문을 설명 필드에 활용.
- 참조 타깃 ID·레벨·외부 클래스 해석은 정적 AST만으로 확정할 수 없으면 공란.

### 7.2 Java Excel 시트 계약

| 순서 | 시트 | 열(기준 샘플) |
|---|---|---|
| 01 | `01_표제부` | 번호 / 항목 / 값 |
| 02 | `02_OBJ정의` | 선언 종류 / OBJ명 / 선언 타입 / 수식어 / 수명 / 초기화 원문 / 소스 행 / 소속 |
| 03 | `03_메서드정의` | 메서드명 / 메서드 ID(인자) / 파라미터 타입 / 반환 타입 / 시작 행 / 끝 행 / 처리 단계 수 |
| 04 | `04_처리단계` | 소속 메서드 / 순번 / 단계 유형 / 소스 행 / 분기 경로 / 소스 스니펫 / 호출 대상 ID |
| 05 | `05_호출관계` | 소스 행 / 호출자 메서드 / 호출 메서드 / 대상 ID |
| 06 | `06_타입참조` | 소스 행 / 참조 종류 / 타입명 / resolvedClassId |
| 07 | `07_Import` | 타입 단축명 / Import 경로 / 소스 행 |
| 08 | `08_원본경로` | 구분 / 상대 경로 / 원본 위치 |
| 09 | `상세 사양` | NAME / VISIBILITY / LEVEL / DESCRIPTION / DETAIL (PSEUDO CODE) / Input Parameter / Return Type |

`상세 사양`은 **각 메서드가 행으로 나오는 단일 시트**다. `LEVEL`이 확인되지 않으면 공란, `DESCRIPTION`은 원문 JavaDoc 등 근거 없으면 공란이다. `DETAIL (PSEUDO CODE)`라는 열 이름을 쓰되, 실제 값은 **소스에서 추출한 구조화 처리 단계**의 원문·행·분기 경로다. AI가 작성한 의사코드나 업무 설명을 넣지 않는다.

단계 목록은 소스 위치·AST 부모 관계를 기준으로 **결정론적으로** 산출한다. 동행·중첩 표현식의 상대 순서는 테스트로 고정하며 동일 입력에서 임의로 달라지지 않아야 한다. 실제 소스 순서와 다르게 정렬되는 결함은 기준 샘플과 함께 검증한다.

`05_호출관계`는 호출 표현식의 존재를 기록할 뿐, 단순한 메서드 이름 일치만으로 호출 대상을 확정하지 않는다.

## 8. JSP 분석/출력 계약

### 8.1 분석

PMD JSP Parser를 Java 라이브러리로 직접 호출해 정적 AST를 얻는다.

- JSP directive/include, HTML/JSP/커스텀 태그, 속성 원문, EL 표현식 원문, 정적 소스 위치.
- `form:form`의 `commandName`, `form:input`/`form:hidden`의 `path` 등 **원문에 있는** 화면 필드 후보.
- `c:forEach`의 `items`, `var` 등 문서 내부 구조. `var`는 **JSP 내 반복 변수**이며 전역 변수로 분류하지 않는다.
- **확정 이벤트 규칙:** JSP 실제 소스에서 확인되는 `<a href="...">표시문구</a>`는 **사용자 링크 클릭(LINK_CLICK)**으로 인정한다. JavaScript의 `onclick` 존재 여부와 무관하게 추출한다. `Type=LINK_CLICK`, `Name`은 링크의 실제 표시 텍스트, `설명`은 `href="..."` 원문, `Return`은 공란이다. 화면 동작의 업무 목적이나 컨트롤러 호출은 추정하지 않는다.
- EL 필드/객체 연결은 소스 문맥에서 확정 가능한 것만 기록한다. 모호하면 공란.
- `LINK_CLICK` 추출에 JavaScript 구문 분석기는 필요하지 않다. `<script>` 내부 함수·JavaScript 이벤트 속성에 대한 **추가적인 구문 분석 범위는 별도 결정 사항**으로 유지한다. 단순 문자열 패턴으로 함수를 꾸며내거나 추측하지 않으며, 별도 승인 없이 JS 분석 라이브러리를 추가하지 않는다.

### 8.2 JSP Excel 시트 계약

| 순서 | 시트 | 열(기준 샘플) |
|---|---|---|
| 01 | `01_표제부` | 번호 / 항목 / 값 |
| 02 | `02_화면필드정의` | 화면 필드 / Object / 참조 필드 / Edit / Remark (속성 원문) / 항목 유형 / 다국어 ID / 소스 행 |
| 03 | `03_최소흐름` | `순번` · `소스 행` · `AST 노드 종류` · `태그 / 파일` · `속성` · `AST 깊이` |
| 04 | `04_원본경로` | 구분 / 상대 경로 / 원본 위치 |
| 05 | `상세 사양` | 하단의 세 블록 |

**주의:** `03_최소흐름`의 열 헤더는 물리적으로 **6개**다: `순번 | 소스 행 | AST 노드 종류 | 태그 / 파일 | 속성 | AST 깊이`. 위 테이블의 `태그 / 파일`은 **단일 헤더**다. 이 시트는 JSP AST의 구조 출현 순서를 뜻하며, 실행 시점의 동적 제어 흐름을 의미하지 않는다.

`상세 사양` 시트의 블록:

1. **상수 및 전역 변수**: `상수/변수명 | Type | 설명 | 비고`. 원문 선언이 없으면 빈 행 유지.
2. **Function 및 Event**: `Type | Name | 설명 | Return`. 확인된 `<a href>`는 JavaScript 코드가 없어도 `LINK_CLICK` 이벤트 행을 작성한다. 예: `Update` / `href="/update-todo?id=${todo.id}"`, `Delete` / `href="/delete-todo?id=${todo.id}"`, `Add` / `href="/add-todo"`. 동작 의미는 보충하지 않는다.
3. **명세 변경 사항**: `NO | Source명 | Source Code | 개발자 | 변경 내용`. 최초 생성 시 **공란**.

화면 필드의 `Edit` 등 확정 근거가 부족한 값은 채우지 않는다. 특히 JSP 태그 존재만으로 비즈니스 수정 가능성을 단정하지 않는다. JavaScript 함수와 링크 클릭을 동일한 호출로 오인하지 않는다.

## 9. GUI / CLI 및 공통 실행 설계

### 9.1 UI의 기능적 구조

Swing 기반 **비웹 데스크톱** 화면에 다음 기능을 제공한다.

- **공통 설정 패널**: Java/JSP 단일 모드 선택, 시스템, 작성자, **작성일(선택적 변경, 미입력 시 파일별 수정일)**, 프로그램명, 프로그램 개요, 출력 폴더, Excel 형식.
- **모듈 패널**: 폴더 Drop Zone, [+ 폴더 추가] 버튼, `서브 시스템(수정 가능) | 모듈(수정 가능) | 선택한 소스 폴더(읽기 전용) | 제거(X)` 표.
- 선택된 모듈 수·분석 유형·출력 폴더 등을 확인한 뒤 **사양서 생성**.
- 진행·완료·실패 결과를 확인하되, 원본 소스 코드를 UI 로그에 불필요하게 노출하지 않는다.

UI의 색상·세부 픽셀·창 크기는 **기존 시안에서 아직 최종 승인되지 않은 영역**이다. **Excel의 그레이스케일 원칙과 GUI 테마 결정을 혼동하지 않는다.**

### 9.2 CLI의 동일한 입력 규약

GUI와 CLI는 **공통 설정 모델 / 파일 목록 생성 / 분석 코어 / Excel 작성기**를 그대로 공유한다.

계획하는 진입점(예시; 실제 명령 옵션은 구현 계획에서 고정):

```text
java -jar spec-generator.jar gui
java -jar spec-generator.jar generate --config C:\path\job.json
```

다중 폴더를 표현하는 설정 스키마 **제안**:

```json
{
  "mode": "JAVA",
  "system": "SYS1",
  "author": "",
  "authoringDateOverride": null,
  "programName": "",
  "overview": "",
  "outputDirectory": "D:\\SpecOutput",
  "outputFormat": "xls",
  "modules": [
    {
      "sourceFolder": "C:\\SYS1_PJT1\\src\\main\\java\\ext\\sys1\\module1",
      "subsystem": "SYS1",
      "moduleName": "module1"
    }
  ]
}
```

CLI 설정 파일에도 사용자 입력한 모듈 표시명·서브시스템명과 동일한 정책을 적용한다. CLI로 실행할 때 Swing 창을 띄우지 않는다.

### 9.3 내부 컴포넌트 경계

```text
Swing UI / CLI
   -> JobConfig + ModuleSelection
   -> Scanner (모드별 확장자·폴더 중복·경로 충돌)
   -> JavaParserAdapter | PmdJspParserAdapter
   -> SourceFacts (원문, 소스 위치, 선언/구조 정보)
   -> SpecMapper (시트별 확정 규칙)
   -> ApachePoiWriter (XLS / XLSX)
   -> FileResult + RunSummary
```

분석기와 Excel 출력기는 서로 직접 의존하지 않도록 **소스 사실 기반의 중간 모델**을 둔다. 파서가 바뀌어도 시트 규약·그레이스케일 디자인은 유지한다. 별도 웹 서비스·DB·백그라운드 에이전트는 도입하지 않는다.

## 10. 보안과 운영 제약

1. 실행 시 **네트워크 연결 불필요**. 설치된 의존성을 인터넷에서 다운로드하거나 원격 호출하지 않는다.
2. 선택한 소스 파일은 **읽기 전용**으로 열고, 실행·컴파일·수정하지 않는다.
3. 소스 내용을 임의 파일·원격 서비스·예외 메시지에 덤프하지 않는다. 파일별 실패 상태와 필요한 최소 경로·원인만 기록한다.
4. 동봉 라이브러리 및 전이 의존성의 버전 고정, 라이선스 목록, 해시/SBOM 등 보안 검토 자료를 배포물과 함께 제공한다.
5. 출력 폴더 이외의 장소에 사양서·소스 원문을 남기지 않는다. 작업용 임시 파일 사용 시 정리·접근권한을 보장한다.
6. 경로 정규화, 심볼릭 링크/정션으로 인한 분석 범위 밖 이동 방지, 경로 충돌 검사, 파일명 검증.
7. 배포물은 실행 소스·빌드 규약을 검토할 수 있어야 한다. **오픈소스라는 사실만으로 보안 승인을 보장하지 않는다.**

## 11. 배포 구성

### 11.1 기본: JRE 17+ 실행형

- 제품 JAR과 필요한 라이브러리, 서식이 들어간 **로컬 배포물**.
- 사용자는 호환 Java 17 이상만 있으면 `java -jar ...`로 GUI/CLI 실행 가능.
- 사용자 PC에서 Maven·JDK·Node.js·Python 설치를 요구하지 않는다.

### 11.2 대안: 자체 런타임 동봉

- `jpackage` 애플리케이션 이미지(Windows EXE 실행기 + 포함된 Java 런타임 + 라이브러리)를 제공한다.
- JRE를 별도 설치하기 어려운 사용자에게 설치 없는 **폴더형 실행 패키지**를 우선 제공한다.
- GUI와 CLI는 가능한 한 동일한 Core·동일한 분석/템플릿 리소스를 사용한다.
- 두 배포 형태의 출력이 같은지 Golden Sample로 검증한다.

## 12. 오류 처리 및 결정론

| 조건 | 기대 동작 |
|---|---|
| 빈 폴더 또는 해당 확장자 없음 | 생성 0건을 분명히 알림. 가짜 사양서 미생성 |
| 중복 모듈 폴더 드롭 | 동일 경로는 1건만 유지, 사용자 편집값 보존 |
| 기존 출력 폴더/Excel 존재 | 폴더 재사용, 동일 경로 기존 Excel 파일은 확인 없이 덮어씀 |
| 서로 다른 입력 소스 간 출력 경로 충돌 | 모호한 대상은 사전 차단·충돌 보고 (기존 파일 재생성과는 구분) |
| 일부 Java/JSP 파일 파싱 오류 | 해당 파일을 실패로 구분. 나머지 파일은 계속 처리 (제안 정책) |
| 알 수 없는 AST 참조/데이터 | 공란. 호출 대상 ID·설명 임의 채움 금지 |
| 권한·입출력 오류 | 해당 파일 경로·오류 유형을 요약하여 사용자에게 제공 |
| `.xls` 표현 한계 초과 | 실패 원인과 `.xlsx` 전환 안내. 조용한 절단 금지 |
| 같은 입력·설정·소스 메타데이터 | 동일한 시트 데이터/순서/서식을 재현 |

로그에는 성공·실패·스킵 개수, 처리한 소스 경로, 생성 Excel 경로를 남길 수 있으나 **전체 소스 원문은 기본적으로 출력하지 않는다**.

| AC-07 | JSP 사실 추출 | 화면 필드, EL, 태그, JavaScript가 없어도 `<a href>`를 `LINK_CLICK`으로 기록. 기준 샘플 3개(Update/Delete/Add)와 원문 `href` 일치 |
| AC-08 | Excel 스키마 | Java 9시트·JSP 5시트, 표제부 10항목, 시트 헤더/공란/순서 일치 |
| AC-09 | 출력 스타일 | 설명성 2행 없음, 전체 무채색, 제목·본문·표 헤더 구조 일치 |
| AC-10 | 무추론 | 알 수 없는 레벨/설명/호출 대상 등은 공란 |
| AC-11 | JRE 호환 | JDK21에서 `--release 17` 빌드, 실제 JRE17에서 GUI·CLI 실행 검증 |
| AC-12 | 독립 배포 | 런타임 동봉 패키지에서 Java 별도 설치 없이 GUI/CLI 실행 |
| AC-13 | 오프라인 | 네트워크 단절 상태에서도 동일 결과, 런타임 외부 연결 없음 |
| AC-14 | 안전한 실패 | 파싱 실패·중복·서로 다른 입력 간 경로 충돌·한계 초과 시 소스 보존 및 명확한 결과 기록 |
| AC-15 | 작성일 | 기본은 파일별 최종 수정일, GUI/CLI 지정일이 있으면 우선 적용 |

검증은 단순히 셀 숫자만 비교하지 않는다. **시트 구성, 자료 필드, 실제 소스 행, 공란, 처리단계 순서, 헤더와 그레이스케일**을 함께 검사한다. `.xls`와 기준 `.xlsx`는 Excel 포맷이 다르므로 내부 바이트 비교가 아닌 **의미·시각 구조 기준**으로 비교한다.

## 14. 완료 상태 / 남은 검증

- **완료된 탐색**: JavaParser로 샘플 `TodoController.java` 메서드 9개 인식; PMD JSP Parser로 샘플 JSP 5개 구문 분석 성공, `list-todos.jsp`의 링크 3개·태그·EL 속성 추출.
- **완료된 디자인 검토 자료**: Java 2건, JSP 2건의 **그레이스케일 Excel 샘플**.
- **미구현**: 제품용 AST Visitor, 사실/시트 매퍼, POI Excel 출력 엔진, CLI/Swing, 안전한 충돌 관리, JRE17/오프라인 배포 테스트.
- **검증 필요**: 복잡한 레거시 JSP(스크립틀릿·커스텀 태그·문법 오류), Java 메서드 복합 분기 순서, 긴 `.xls` 셀, 유효하지 않은 경로·권한, 동일 폴더명 충돌, 라이브러리 보안·라이선스.

## 15. 승인 전 확인할 열린 항목

아래는 **이미 확정된 조건을 뒤집지 않으면서**, 제품 구현에서 정확한 동작을 고정하기 위해 남긴 사항이다.

1. **서로 겹치는 소스 폴더 선택**: 상위·하위 폴더를 함께 등록했을 때 1:1 보장을 위해 차단 또는 명시적 우선순위를 둘지.
2. **추가 JavaScript 구문 분석(후속 선택)**: `<a href>`의 `LINK_CLICK`은 **확정·필수**이며, 별도로 `<script>` 함수나 `onclick` 등의 상세 분석을 확대할지는 후속 검토한다. 이 미결정 사항이 링크 이벤트 구현을 막지 않는다.
3. **기준 Excel 실물 파일**: GitHub 내부에 저장할 위치 및 Golden Sample 보관 방침.

**확정 및 반영:** 작성일은 파일시스템 최종 수정일을 기본으로 하고 사용자가 변경 가능하다. 기존 출력 폴더는 재사용하고 기존 Excel은 확인 없이 덮어쓴다.

위 항목들은 **기본 제품 설계 승인과 분리해 후속 확정 가능**하나, 해당 기능의 구현 전에 결론을 내고 테스트에 반영한다.
