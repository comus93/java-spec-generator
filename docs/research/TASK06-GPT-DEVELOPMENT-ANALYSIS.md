## 2. GPT가 실제로 수행한 개발 순서

아래는 기록으로 확인되는 행동을 정리한 것이며, 상세 호출 순서나 각 단계의 소요 시간을 추정하지 않았다.

1. **작업 범위와 API 파악:** 기준 커밋의 코드, Task 06 요구사항, 기존 테스트 및 JSP 샘플을 근거로 구현 범위를 정했다. PMD JSP 7.29 API를 조사했다. 이전 Terra/DeepSeek 결과 코드를 복사하거나 참고했다는 기록은 없다.
2. **짧은 내부 작업 순서 결정:** 별도 상세 실행 계획서를 새로 만들지 않고, 필드·흐름·이벤트·오류 경계의 핵심 구현 순서를 정했다.
3. **테스트 우선(RED):** `PmdJspAnalyzerTest`를 작성하고 `mvn -q -Dtest=PmdJspAnalyzerTest test`를 실행해 `JspFacts`/`PmdJspAnalyzer` 미구현에 따른 예상 컴파일 실패를 확인했다.
4. **한정된 범위의 구현:** `JspFacts` 사실 모델, PMD JSP 파싱, 태그 필드 추출, JSP 정적 흐름, 원문 속성/EL 유지, JavaScript 분석 없이 `<a href>`에서 `LINK_CLICK` 생성, 파일별 읽기·파싱 오류의 예외 처리를 구현했다.
5. **PASS 확인:** 대상 테스트 5개와 `mvn -q test` 전체 50개가 통과했다.
6. **범위 확인과 커밋:** Git 스테이징/공백 검사를 수행하고 끝 줄바꿈 문제를 수정한 후, 5개 파일 +370줄을 `feat: extract JSP fields and link events` 메시지로 커밋했다. 작업 트리 clean 상태를 확인했다.

직접 GPT 구현은 **개발 계획서의 Task 06을 열람하지 않았다는 대화 기록**이 있다. 반면 앞선 Paseo 개발자 3회는 브리프와 함께 해당 계획서의 Task 06을 실제 열람한 것으로 이전 실행 기록에서 확인됐다.

**내 해석:** 'GPT 추론이 더 빠르다'는 모델 단독 효과가 입증된 것은 아니다. 이 측정으로 확인되는 것은 **특정 실행 구성에서 GPT + AgentDock 직접 경로가 가장 먼저 커밋했다**는 사실이다. 이전 실행 결과와 시간을 GPT가 이미 알고 있었고, 각 후보는 독립 테스트를 작성했으며 단일 실행만 있다. 따라서 학습·환경·도구·문서·구현량·표본 변동성이 혼재한다.

## 5. 개선 기회: 다른 에이전트에 적용 가능한 실험 아이디어

1. **요구사항과 실행 절차를 분리:** 구현 필수 수용 기준은 간결하게 고정하고, 상세 계획은 참고 자료로 제공하되 사용 여부를 기록한다. 계획서가 지나치게 구체적이어서 불필요한 절차를 강제하지 않는지 검토한다.
2. **작업 시작 전 컨텍스트 조건 통일:** 동일 기준 커밋, 저장소 규칙, JDK/Maven 경로, API 문서 접근권과 캐시 상태를 맞춘다.
3. **TDD는 유지하되 단계 시간을 측정:** RED 실패 → 핵심 구현 → 대상 PASS → 전체 PASS → 커밋의 시각을 기록한다. 테스트 자체를 생략해 속도를 얻지 않는다.
4. **직접 호출과 오케스트레이션 오버헤드 분리:** 코딩 모델의 순수 작업 시간, 환경 준비, 전달 대기, 도구 호출, 최종 보고 시간을 각각 측정한다.
5. **공통 수용 테스트로 품질 검증:** 개발자가 쓴 자체 테스트 외에 숨겨진 동일 테스트 세트로 네 구현을 검증한 뒤 속도와 품질을 함께 비교한다.
6. **반복 실행:** 동일 조건에서 최소 여러 번 실행하고 중앙값·범위, 실패율을 함께 본다.

## 6. 다음 비교 실험에서 지켜야 할 원칙

- 신규 GPT 재측정은 기존 후보 코드를 보지 않고, 같은 기준 커밋에서 별도 워크트리로 시작한다.
- `TASK-06-BRIEF.md`를 UTF-8로 읽고, Task 06 계획서 **참고 허용** 조건 및 RED→PASS 명령을 다른 개발자와 일치시킨다.
- 계획서를 실제 읽었는지, 개발을 시작한 시각, 각 테스트/커밋/종료 시각을 기록한다.
- 완료 속도 순위와 코드 품질 판정을 분리한다.
- 로컬 벤치마크 원시 기록과 실제 Git 코드 브랜치가 원격에 아직 없을 수 있으므로, GitHub의 분석 문서만으로 원시 실행의 재현 가능성을 주장하지 않는다.
